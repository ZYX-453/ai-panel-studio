## 1. 三个核心决策（已定）

| 编号 | 决策 | 落地位置 |
|---|---|---|
| D1 | 结束条件 = 软条件收敛 + 硬上限 24 轮，必须落 `ended_reason` | PRD §3 D1 |
| D2 | 发言顺序 = **模型提议 + 纯函数裁决**，模型无权决定顺序 | PRD §3 D2 |
| D3 | 共识/分歧 = **单一真相源**，总结只注入 `consensus_state` 不重读 transcript | PRD §3 D3 |

**关于成本约束的调整**：原计划为省额度做"录制回放跑测试"，现确认积分为自有额度且充足，故**取消该限制，开发和 E2E 全部真实调用模型**——这本来就是需求写明的（"不能是预置的假内容"）。

但保留一条与成本无关的理由：**调度器、人设装配、共识版本递增这三块的测试不依赖模型输出**。因为它们是纯函数/纯状态机，测的是"给定状态选谁""给定人设拼什么 prompt""版本号是否 +1"。这不是省钱，是可重复性——模型的输出天然不可断言，把可测的部分切出来测，是 TDD 的前提。

## 4. 核心 Prompt 六段（对应交付物 2 的 ≥5 段）

每段写作格式固定：**意图 → 约束 → 产出 → 挑战 → 如何修正**。后两项必须**事后如实填**，不允许预先编。

| # | 范式 | Prompt 目标 | 预期挑战（待实测确认） |
|---|---|---|---|
| P1 | SDD | 生成 ER 图 + SQLite DDL + 索引 | 模型容易把"内部事件"也建成表 |
| P2 | SDD | 生成 API 契约 + SSE 事件类型表 | 容易把 SSE 写成 WebSocket，或漏掉重放语义 |
| P3 | DDD | 生成组件树 + 设计 token + 三区布局 | 容易用整页滚动，或所有专家同色 |
| P4 | TDD | 只写调度器测试，不写实现（要求红） | 模型倾向"顺手把实现也写了"——必须明确禁止 |
| P5 | TDD | 按测试实现，只改实现不动测试 | 模型爱改测试让它过——必须禁止 |
| P6 | E2E | 端到端脚本 + 门禁 | 容易写成"接口返回 200 就算过" |

**P4/P5 这两段是这个作业里最能拿分的两段。** 因为"禁止一键生成"的核心证据就是：模型在 TDD 阶段被约束住，先红后绿。

另外三段**系统 prompt**（交付物 2 的第 3 项，独立于上面六段）：

1. **主持人 prompt**：控场、追问、串联、收尾；不预设立场；每次 1-2 句；绝不输出 JSON。
2. **专家 prompt（模板 + 人设变量）**：姓名/Title/立场/口头禅/攻击面注入；必须针对上一条具体发言回应；禁止复述他人。
3. **共识抽取 prompt**：只输出结构化 points/disputes；必须给出 `based_on_seq`；合并旧版本时保留未消解的分歧。
